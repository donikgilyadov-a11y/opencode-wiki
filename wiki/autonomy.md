# Автопилот: долгая автономная работа

Плагин `autopilot-tools` и навык `autopilot`. Решение — [0003](../decisions/0003-autonomy.md).

## Зачем

При длинной сессии цель теряется при сжатии контекста, нет журнала шагов и защитного лимита.
Автопилот хранит цель и прогресс на диске и подставляет цель в каждый запрос модели.

## Инструменты

| Инструмент | Назначение |
| --- | --- |
| `autopilot.start(goal, maxSteps?, stopWhen?)` | Поставить цель, лимит шагов и проверяемое стоп-условие |
| `autopilot.status()` | Цель, статус, счётчик, последние шаги |
| `autopilot.progress(note, done?)` | Отметить шаг; `done: false` ставит на паузу |
| `autopilot.checkpoint(note?)` | Зафиксировать состояние вручную |
| `autopilot.stop(reason, success?)` | Завершить с итогом или остановиться с причиной |

## Хуки

- `context` — добавляет компактное напоминание о цели в system каждого запроса модели.
  Благодаря этому цель переживает compaction.
- `compaction` — автоматически пишет чекпоинт при сжатии истории.

## Файлы состояния

```
brain/autonomy/
├── GOAL.json        # цель, статус, шаги, лимит, стоп-условие
├── PROGRESS.md      # журнал шагов
├── CHECKPOINTS.md   # чекпоинты, в том числе авто
└── README.md        # пояснение
```

## Цикл работы

1. `/autopilot <цель>` или `autopilot.start(...)`.
2. Работать маленькими шагами, после каждого — `autopilot.progress`.
3. Важные факты — `brain.save`; рубежи — `autopilot.checkpoint`.
4. Достигнуто `stopWhen` — `autopilot.stop(..., success: true)`.
5. Лимит шагов или блокер — `autopilot.stop(..., success: false)` и доложить пользователю.

## Связь с DCP

Плагин `@tarquinen/opencode-dcp` даёт инструмент `compress`: сжимай завершённые старые куски
диалога, чтобы длинная работа не съедала контекст. Чекпоинты автопилота при этом сохраняют цель.
